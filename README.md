# bitpay-exporter

Export your own transaction history and contacts from the Israeli **Bit** payment app (ביט,
`com.bnhp.payments.paymentsapp`) into PostgreSQL. Bit has no export or API, so this drives the app on
your Android phone over `adb` and parses its screens (`uiautomator dump`).

It is meant for exporting **your own** data from **your own** phone. Check Bit's terms of service before
using it; this project is not affiliated with Bit or Bank Hapoalim.

## What you get

Two tables in a local database `bitpay`:

- **`transactions`**: one row per Bit reference number (`ref`, the primary key): counterparty name and
  phone, direction (`received` / `sent`), amount, note, status (`Done`, `Expired`, `Failed`, ...),
  funding source, exact date and time (`tx_at`), plus every UI node of the list row and of the detail
  screen as jsonb (`list_row`, `detail`).
- **`contacts`**: one row per phone number (digits only, `0541234567`): the name from the phone book, the
  Bit names seen for that contact, when it was last checked, and the raw UI row.

Both have `created_at` and `last_seen_at`. They join on
`transactions.counterparty_phone = contacts.phone`; `transactions.phone_source` says how the phone was
found (`row`, `filter`, `name`, `bit_name`). Merchants (PayMe, pizza chains, ...) and people who aren't in
your phone book have no phone.

```sql
select t.tx_at, t.direction, t.amount, t.note, coalesce(c.name, t.counterparty_name) as who
from transactions t left join contacts c on c.phone = t.counterparty_phone
order by t.tx_at desc;
```

## Requirements

- An Android phone with Bit installed and logged in, USB debugging enabled, visible in `adb devices`.
  The app's UI language must be English (the scraper matches English labels such as "See all").
- `adb`, Python 3.10+ with `psycopg` 3 (`pip install "psycopg[binary]"`), PostgreSQL.

## Setup

```sh
createdb bitpay
cd sql/schema && cat 00 $(cat order.txt) | psql -v ON_ERROR_STOP=1 -d bitpay
```

The scraper connects with `dbname=bitpay` (your unix user, over the local socket).

## Running

```sh
./bitpay_exporter.py            # or: ./run.sh [TMUX-PANE]  -> logs to run.log, notifies that pane
```

A run:

1. opens Bit (launching it if needed), goes to Recent activity, "See all";
2. **activity pass**: scrolls the list; each new row's detail screen gives its reference number and time
   (~5 s per new transaction). Known rows are recognized without opening them; the pass stops after 3
   known rows in a row;
3. **contacts pass**: scrolls the whole "Contact/Number" sheet (~10 min for ~1300 contacts);
4. **filter pass**: maps counterparties to phone numbers in layers: names already confirmed for a
   contact, then an exact match of the counterparty name against the phone book (Bit shows your
   phone-book name for people you have as contacts), then each contact with such a match is verified by
   filtering the activity by that contact (~9 s each); matches the filter doesn't confirm are undone;
5. closes Bit.

The first run reads the whole history (it took ~45 min for ~500 transactions). Later runs only open new
transactions. Measured incremental run with nothing new: 3 s activity pass + the contacts pass, data
unchanged except `last_seen_at`.

### It shares the phone with you

- If Bit leaves the foreground (you open another app, lock the screen) the run **pauses** until Bit is
  back, then starts again from Bit's home screen. If the phone sits on the launcher for 30 s, the scraper
  brings Bit back itself.
- If the phone drops off `adb`, the run waits for it to reconnect.
- An interrupted run is continued by the next one (`.state.json`): finished passes are skipped and the
  activity pass fast-forwards to where it stopped.

### Options

| flag | |
|---|---|
| `--skip activity\|contacts\|filter` | leave out a pass (repeatable) |
| `--stop-after N` | known rows in a row before the activity pass stops (default 3, 0 = scan everything) |
| `--full-sweep` | filter by every contact never checked (the whole phone book, slow) |
| `--only PHONE` | filter by just these contacts (repeatable) |
| `--max-filter N` | at most N filter checks this run |
| `--recheck-all` | filter by every contact again |
| `--keep-open` | don't close Bit at the end |

## Schema changes

`sql/schema/` is the source of truth, one file per object, generated by `pg_schema_dump.py` from the
live database (reads `DBURI` from `.env`, e.g. `DBURI=postgresql:///bitpay`). Change the schema in
psql, run `./pg_schema_dump.py`, commit the diff.

## Caveats

This depends on Bit's screen layout and English labels; an app update can break it. Bit's screens are
Jetpack Compose without resource ids, so rows are recognized by their content (amount `₪…`, a date,
a `· status`). Each `uiautomator dump` takes ~2.3 s and dominates the run time.
